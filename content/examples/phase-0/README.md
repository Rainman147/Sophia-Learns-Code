# Phase 0 Lesson Specimens

Phase 0 assumes no prior programming experience and no hidden familiarity with code editors, consoles, terminals, files, or error messages.

These files are product and content specifications. They are not yet a complete runtime format and may evolve through schema validation and learner testing.

## First five-lesson vertical slice

| Order | Working title | Primary capability | Signature interaction |
|---:|---|---|---|
| 1 | First Contact | Run, change, predict, and repair a `print()` program | Intentional unmatched quote |
| 2 | Names and Values | Use names to refer to and change values | Animated name-to-value map |
| 3 | Make a Decision | Compare values and execute one branch | Predict which route lights up |
| 4 | Repeat the Signal | Trace a small `for` loop | Iteration scrubber |
| 5 | Case 001 | Combine the first capabilities independently | Tiny investigation checkride |

## Absolute-zero content rules

- Introduce every control before requiring it.
- Distinguish code, output, errors, hints, and tests visually and semantically.
- Keep the first successful action under one minute when practical.
- Let the learner personalize something early.
- Ask for prediction before revealing selected outcomes.
- Create one recoverable error intentionally.
- Explain punctuation only when it becomes relevant.
- Avoid unexplained syntax, even in decorative examples.
- Make state changes visible.
- End with a small independent act and a natural stop.
- Schedule retrieval rather than assuming the first success will last.
